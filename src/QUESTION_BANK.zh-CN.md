# 铁路题库贡献与维护

[English](QUESTION_BANK.md) | [简体中文](QUESTION_BANK.zh-CN.md)

## 提交题目

通过[铁路题目 Issue 表单](https://github.com/g497813927/community-seasons/issues/new?template=rail-question.yml)提出新题或修订，每个 Issue 只提交一道题，无需克隆仓库或编辑文档、JSON。修订已有题目时，也需填写完整替换内容，包括两种语言和全部三个选项。

- 选择新增或修订。新题使用尚未占用的稳定 `id`；修订时使用 [`lib/game/rail-questions.json`](lib/game/rail-questions.json) 中已有的 ID。ID 和主题均以小写字母开头，使用小写字母或数字，以单个连字符分隔，例如 `respectful-disagreement`。
- 填写英语和简体中文题干、恰好三个双语选项，以及每个选项各自的双语解析，错误选项也需提供。双语含义应一致，且只能有一个明确、站得住脚的正确答案。
- 按表单顺序选择正确选项 **1、2 或 3**。维护者将其对应到 JSON 的 `correctIndex` **0、1 或 2**；游戏会打乱答案所在轨道。
- 可选的审阅说明和来源参考仅供维护者审阅，不会导入游戏；维护者在将来源元数据加入审阅 JSON 前会人工核实。题目文字应使用虚构、脱敏的情境，不包含真实姓名或账号身份。

| 文本 | 英语上限 | 简体中文上限 |
| --- | --- | --- |
| 题干 | 180 字符 | 90 字符 |
| 每个选项文本 | 72 字符 | 36 字符 |
| 每个选项解析 | 240 字符 | 120 字符 |

提交后，**Check rail question** 会发布或更新自己的机器人反馈评论，并写入 Actions 摘要。检查包括必填字段、ID、双语文本、重复题干和选项、答案选择及题库长度限制。修改 Issue 正文即可重新检查，请保留表单的字段标题；重新打开 Issue 时也会检查。无关 Issue 会被跳过。工作流合并到默认分支后才会生效。

检查通过仅表示结构符合要求。教学准确性、翻译质量与来源适用性仍需维护者审阅；Issue 不会自动导入或发布。工作流详情见 [CI 指南](../docs/CI.zh-CN.md)。如需离线检查，可将 Issue 正文保存为 Markdown，再从仓库根目录执行：

```sh
node scripts/check-rail-question.mjs --body /path/to/issue.md
```

## 维护者整合

审阅后，维护者将采纳的内容整合进 **`lib/game/rail-questions.json`**。此 JSON 是游戏题库的数据源。修订原题时保留已有 ID，并人工核实可选的 `source` 元数据。所有示例均为虚构教学情境，不引用真实用户原文，也不声称复现平台官方处理决定。

每道题包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定、唯一的标识；修改已有题目时保留。 |
| `topic` | 便于审阅和整理的主题。 |
| `prompt.en`, `prompt.zh` | 英语和简体中文题干。 |
| `options` | 按 JSON 顺序排列，必须恰好有三个选项。 |
| `options[].label.en`, `.zh` | 双语选项文本。 |
| `options[].why.en`, `.zh` | 玩家选择该项后显示的双语解析；错误选项也需提供。 |
| `correctIndex` | **0 为第一项，1 为第二项，2 为第三项。** |
| `source`（可选） | 仅供审阅的来源动态、账号、日期、段落及改编说明，不进入游戏或分享卡片。 |

题库包含虚构情境题，以及依据公开治理动态改编的虚构题。有来源的改编题通过 `source.dateType` 区分发布时间与页面显示的编辑时间。来源账号、真实事件、真实姓名和链接仅保留在审阅 JSON 中；生成的游戏数据只包含改编后的题目和答案。

`correctIndex` **不对应固定的左、中、右轨道**：游戏会为每题打乱选项顺序。每次小车行程仍抽取 3–4 道不重复的题；增加题库只会扩大抽题范围，不会延长单次行程。

会话题组会在重试和补充题目时保留近期出题保护。修改抽题或重新洗牌逻辑时，必须保留这项保护：重试不得丢弃近期出题记录，也不得消耗玩家尚未看到的题目。

答案判定后，可点击**分享这道题**，用当前语言将虚构题干、正确答案及该答案的解析生成学习卡。障碍物观察站也可通过**分享这份提醒**，分享脱敏示例和建议回应。打开铁路学习卡会暂停游戏；关闭后，准备好再按继续。卡片使用 Toy 默认游戏二维码，不包含真实案例来源链接或账号身份。任何内容都不会自动分享或保存。

保持双语含义一致，每题只有一个明确、站得住脚的正确答案，并为每个选项提供针对该项的解析。选项应简短，适合手机屏幕。敏感内容使用 `[insult]` / `[侮辱词]` 等占位符。不要添加真实姓名或未经核实的案例链接。

整合已审阅的题目后，在仓库根目录执行：

```sh
npm --prefix src run questions:sync
npm --prefix src run questions:validate
npm test
npm run build
```

`npm run dev` 和 `npm run build` 会在启动前自动同步 JSON。开发服务器已经运行时，如果修改了 JSON，请在仓库根目录运行一次 `npm --prefix src run questions:sync` 以更新游戏。JSON 格式错误、翻译缺失、ID 重复、选项重复、答案索引无效或文本过长，都会导致校验失败，并报告具体字段位置。校验只检查结构，不判断答案在教学上是否正确；发布前仍需审阅内容。

`lib/game/railway.ts` 内的 `RAIL_QUESTIONS` 区段由脚本生成。请编辑 JSON，不要直接修改该生成区段；铁路的其余逻辑不受题库同步影响。
