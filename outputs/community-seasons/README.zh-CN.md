# Community Seasons / 四季共建

[English](README.md) | [简体中文](README.zh-CN.md)

一款支持键盘和滑动操作的双语学习跑酷游戏，带你穿行四季社区。持续奔跑、收集金币，学习辨识不当帖子。

## 运行与构建

使用 Node.js 22.13 或更高版本，推荐 Node 24。

```sh
npm ci
npm run dev -- --port 3001
npm run build
npm run preview
```

将 `dist/` 中的全部文件上传到任意静态网站服务器即可托管。构建使用相对资源 URL，支持部署到以斜杠结尾的子目录。`vercel.json` 配置了 Vite 构建；`deploy/nginx.conf` 是自有服务器的配置示例。游戏运行不需要后端服务、API 密钥或数据库。

## 学习流程

障碍物是带文字标签的评论卡：跳过低矮卡片、从横幅下方滑过，或换道避开高大的帖子堆。失误后，捣乱评论者会从后方追赶。撞到帖子时，游戏暂停并打开观察站，展示经过脱敏的虚构示例、解释、建设性的回应方式，以及更尊重他人的改写。受到保护时，碰撞仍正常消耗护盾；致命碰撞在学习结束后仍会结束本局。撞到帖子并不表示玩家认同其内容。

学习内容中的参考链接会在新标签页打开公开的哔哩哔哩社区治理案例。相关真实案例与虚构示例分别呈现；没有经过核实的对应案例时，链接会明确指向案例总览。在线来源页面可能变化，也可能要求登录。本游戏是独立教育作品，不代表哔哩哔哩，也不预测平台处理决定。

首次启动时，游戏会采用浏览器首选且受支持的语言：英语或简体中文。手动选择的语言会被记住，并在后续访问中优先使用。

## 保存进度

在 Toy 中，登录玩家可以通过同一账号跨设备同步金币钱包、已购买道具库存、技能解锁、升级等级、已装备技能、最高分和上次游玩的季节。玩家选择使用哪份存档之前，现有浏览器进度会保留。本地与云端存档不同时，对比对话框提供**使用云存档**、**使用本机存档**和**仅使用本机存档**三个选项。云端存档为空时，上传已有浏览器进度也需要玩家选择。选择存档会用完整的一份替换另一份；余额和已购物品不会相加。

云存储或登录不可用时，浏览器存档仍可使用。主界面显示同步状态，并提供重试或启用云同步的入口。每局开始前，游戏会检查云端是否有变化；迟到的响应不能替换正在进行的游戏进度。仅本地模式会一直保留，直到玩家再次启用云同步。包括自行托管版本在内的独立构建只使用浏览器存储，不加载 Toy SDK。

正在进行的局、当局金币计数、距离、临时加速计时器和技能能量都不会在另一台设备上恢复。语言、声音和新手引导偏好按设备保留。

Toy 实现说明：SDK 在 `community-seasons-save-v1` 下保存一个带版本的 JSON 值，控制在单个值 1,024 字节的限制内。本地变更约每三秒合并一次，写入按顺序执行。唯一修订标识和每次写入前的读取用于检测云端存档变化，必要时再次请求玩家选择。Toy 不提供原子的比较并交换（compare-and-swap）操作，因此不同设备上真正同时发生的写入仍可能产生竞争。

## 操作

- 方向键 / WASD：换道、跳跃、滑行。空格键也可跳跃。
- 手机：向左、右、上、下滑动。点击技能按钮，或双击跑道，使用已充满能量的技能。
- E：永久技能。P：暂停。M：静音/取消静音。B：商店。
- 点击道具图标按钮，或按 1：友善启程；2：界限护盾；3：共建双倍；4：四季通行。界限护盾和共建双倍整局均可使用；友善启程和四季通行仅在开局前五秒可用。

每个季节都有独立的背景音乐。常规速度逐步升至 5.5 倍；短金币路径会引导玩家经过多条跑道；超过此前最高分时会显示短暂的庆祝提示。观察站暂停期间，当局所有计时器都会冻结。详见[玩法指南](GAMEPLAY.zh-CN.md)。

道路岔口向左或向右转弯；偶尔出现的社区快线小车会用 3–4 道选道题替代躲避障碍。入口会预览接下来的活动；最后一题答对后，小车继续驶入同一座出口门，再通过融入当前季节色彩的隧道回到跑酷。小车速度和奖励随常规跑酷进度提高，但题目阅读时间保持不变。铁路上仍会累计距离和分数。每个季节都有专属地标和建筑。障碍间距将不规则的密集段与喘息空间混合，并缩短转弯和车站周围的留空距离。跑道上的强化道具间隔更远，随机间距会考虑跑步速度。边缘误操作会触发向内回弹和半秒保护。完整规则见[玩法指南](GAMEPLAY.zh-CN.md)。

铁路题库包含 47 道双语教学题，使用会话题组避免近期重复，包括补充题组和重试之后。编辑 `lib/game/rail-questions.json` 可审阅题目、选项、正确答案和解析。字段说明与校验命令见[题库指南](QUESTION_BANK.zh-CN.md)。开发服务器和生产构建会在启动前将此 JSON 同步到游戏中。

“开源许可”按钮位于游戏和操作说明下方。可搜索的面板仅在打开时加载 `public/open-source-licenses.json`，并在面板内直接显示原始声明，不提供超链接或外部跳转。原始许可证文本中的 URL 保持为纯文本。打开面板会暂停正在进行的游戏。`public/THIRD-PARTY-NOTICES.txt` 也包含完整声明，可供开发和分发使用。两份文件覆盖本项目 npm 锁文件中已安装的软件包，包括间接依赖和开发工具。“生产/开发”标签描述 npm 的依赖分类，并不表示列表中的每个包都会打入浏览器产物。未安装的可选平台包单独列出。外部平台服务以及独立模糊测试、手机测试工作区中的工具不在本清单范围内。

执行 `npm ci` 或更新依赖后，运行 `npm run licenses:generate`；`npm run licenses:check` 用于检查生成结果是否最新。生产构建会在类型检查和打包前生成清单。缺少必需包、无法确定许可证、固定补充文件变化或生成结果过期，都会导致校验失败。生成过程不使用网络，并逐字保留版权行和嵌套的第三方声明。

Rolldown 的 npm 归档可能遗漏原生包的许可证文件及引用的第三方声明。已核实的上游原始文件按版本保存在 `scripts/license-supplements/` 下的各个目录中；生成的声明包含来源 URL，`scripts/licenses.mjs` 使用固定的 SHA-256 进行校验。已安装版本以 `package-lock.json` 为准，生成器支持的补充文件版本以脚本中的规则为准。添加新版本时应保留此前已核实的目录，不得用通用许可证模板替代。

生成器可直接复用，无需安装额外工具。对其他 npm 项目独立运行、指定输出目录和在 CI 中校验的方法，见[许可证生成器指南](scripts/LICENSE_GENERATOR.zh-CN.md)。
