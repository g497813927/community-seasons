# Toy 排行榜

[English](LEADERBOARD.md) | [简体中文](LEADERBOARD.zh-CN.md)

四季共建使用 Toy 的 **2 号榜位**记录当前难度规则下的成绩，游戏只显示**今日**和**本周**榜单。读取榜单和个人名次时，必须显式传入榜位与周期；不显示或查询总榜，也不导入存档中的个人最高分。玩家须先为当前 Toy 账号主动加入，之后新完成且通过检查的对局才会在同账号的设备间自动提交。

## 隐私与同意

所有玩家均显示为**隐藏姓名**，不显示账号头像或个人主页链接。排行榜不请求用户资料；Toy 返回的昵称和头像在进入游戏界面之前即被丢弃。

这保护的是游戏内的展示隐私，并不表示向 Toy 匿名提交。提交仍使用玩家已登录的哔哩哔哩账号，Toy 也可能展示自己的数据授权确认。**加入排行榜并提交本局成绩**按钮前应说明账号用途和之后的自动提交行为。玩家明确选择该操作，并完成 Toy 要求的授权之前，不得提交任何成绩。

参与选择仅保存在账号的独立 Toy 云存储键 `community-seasons-leaderboard-consent-v1` 中，值须严格符合 JSON 对象 `{ "version": 1, "enabled": true }` 或 `{ "version": 1, "enabled": false }`。不得用 `localStorage` 保存同意状态。此键与游戏进度存档独立，改变参与选择不得替换金币余额、购物记录、装扮或最高分。

首次加入会在 Toy 授权完成后提交当前有效对局，只有确认提交成功后才写入启用偏好；偏好也确认保存成功后，才开始自动参与。如果成绩已提交但偏好保存失败，应分别说明：本局已经上榜，自动提交仍关闭。重试保存选择时，不得再次提交该成绩。

初始化、打开排行榜及每次符合条件的自动提交之前，均从云端读取参与选择。缺少同意记录不能启用参与；云端不可用或数据格式异常时，也须关闭自动提交并保留本地成绩，不得退回设备本地的同意状态。有效的启用记录允许之后新完成且符合条件的每局自动提交一次，包括同账号登录的其他设备。正常流程无须逐局点击或接受游戏内确认；Toy 仍可能要求重新授予平台权限。

选择**暂不加入**或拒绝 Toy 授权时，保存 `enabled: false`，尚未提交的成绩保留在本地。如果成绩已被接受、只是参与选择保存失败，再选择暂不加入只会关闭之后的自动提交，不会撤回已接受的成绩。禁用偏好写入失败时，继续关闭自动提交，并提示选择尚未同步。关闭邀请不会启用参与，之后仍可主动加入。首次成绩提交失败或结果不确定时，不得启用同意状态；拒绝后不得自动重试。刷新页面、读取存档或启用云同步时，均不得提交保存的最高分或上次页面会话的最后一局。玩家可以查看公开榜单并继续游玩，无须加入。

当前 SDK 不接受自定义昵称、匿名参数或逐条记录的隐私设置。宿主页在授权遭拒时返回 `type: 'user_denied'`。本地隐藏姓名无法改变 Toy 持有或返回的账号资料，也不能通过名次、分数或头像推测身份。参见[官方 SDK 文档](https://www.bilibili.com/toy/publish/sdk)和[宿主转发实现](https://s1.hdslb.com/bfs/seed/toy/app/sdk/toy-host.js)。

## API 约定

2026-09-21 已核对用户提供的 `toy.d.ts`、`toy-js-sdk-abilities.md`、[官方文档](https://www.bilibili.com/toy/publish/sdk)和[当前 SDK](https://s1.hdslb.com/bfs/seed/toy/app/sdk/toy-sdk.js)。

| API | 参数与返回值 |
| --- | --- |
| `submitScore` | `{ board, score }` → `{ score }`。需要登录和平台授权；提交的是绝对成绩，不是增量。 |
| `getRankList` | `{ board, period, limit }` → `{ rank, score, nickname, avatar }[]`。游客可读，最多返回 100 条。 |
| `getMyRank` | `{ board, period }` → `{ ranked, rank, score }`。需要登录；是否上榜须检查 `ranked`。 |

Toy 接受 −16,777,216 至 16,777,215 的整数分数；游戏另行要求当局分数为正，并通过完整性检查。榜单按分数从高到低排列，同分时先达成者在前。更高成绩会更新个人最佳，较低成绩不会覆盖它。重复提交仍会消耗请求额度。

Toy 支持 `all`、`month`、`week`、`day`，默认值是 `all`；本游戏只允许 `day` 与 `week`。`submitScore` 没有周期参数，返回的是总榜最高分；显示所选周期时应忽略该返回值，另用相同周期的 `getMyRank` 读取。**Toy 内部仍会保留总榜记录。** SDK 不支持在使用排行榜的同时禁用这项存储。

用户提供的声明与能力快照写的是 1–3 号榜位；当前官方参数表和 SDK 校验已允许 1–5，使用 2 号榜位与两者均兼容。[当日核对的文档资源](https://s1.hdslb.com/bfs/static/toy/app/publish/assets/index-DBBHFmUO.js)含当前参数表。公开榜单记录没有时间戳、规则版本、对局证明或稳定用户标识。以后出现不兼容的难度调整，应换用尚未使用的榜位，不能继续混入 2 号榜位。SDK 没有榜位重置 API。

按需读取榜单，由玩家主动刷新。加入成功且云端偏好确认保存后，每个新完成且符合条件的对局先重新检查云端同意状态，再提交一次。不可用、未登录、拒绝授权、超时或返回值异常时，应提示状态并保留正常游玩。Toy 限流可能返回 `type: 'http_error', code: 307044`；不要轮询、并发提交或立即循环重试。云存档协调时不得提交保存的最高分，也不得重新提交上次页面会话的对局。

## 分数检查的边界

客户端检查当局是否在当前游戏会话中开始、是否已经结束，以及分数、距离、所得金币和经过时间是否一致并符合游戏的数值与移动限制。历史纪录和云端导入的最高分不具备提交资格。调用 SDK 前检查结果，防止重复提交同一局；异常成绩应被拒绝，不能截断成允许范围内的最高分。

例如，把本地存储中的最高分改成 **999,999,999,999,999**，不能生成有效对局或触发上传；即使已经记住参与选择并刷新页面，也不能上榜。包含该值的伪造提交对象会在任何排行榜 SDK 访问之前被拒绝。只有当前页面会话中真实完成的一局所生成的完整性凭证，才能进入提交路径；记住参与选择只代表同意参与，并不是成绩证明。

这些检查能阻止正常游戏流程中的意外损坏和简单改分，**不等于可信的服务端验证**。Toy 公开提交 API 只接收榜位和分数，没有签名对局令牌、回放证明或开发者验证回调。控制浏览器的玩家仍可绕过游戏客户端，直接调用 SDK。把校验和或密钥放进游戏也无法改变这个信任边界。严格防作弊需要权威验证服务，以及无法绕过验证的提交入口；本次接入没有提供这两项能力。

读取的成绩也属于不可信数据，应拒绝结构异常或不支持的数值，但不能把看起来合理的分数宣称为已验证成绩。Toy 创作者管理界面支持移除成绩和限制写入，这是独立的人工管理操作，不是自动对局验证。该操作可能影响某位用户在当前 Toy 全部榜位的成绩，不得由游戏自动执行。

## QA 与发布

使用隔离的 SDK 测试替身覆盖可用、不可用、未登录、拒绝授权、空榜、异常数据和失败状态，并检查双语、键盘与触屏操作、放大文字、日周榜切换以及姓名头像隐藏。验证加入前不提交、首次明确成功后才启用云端偏好、每次后续自动提交前重查偏好、跨设备选择，以及暂不加入和拒绝授权保存禁用状态。验证云端不可用或格式异常时不提交、重试保存选择不重复上传已成功的成绩，以及偏好写入不覆盖进度存档。刷新后不得上传最高分或上一局。包含数值恰为 **999,999,999,999,999** 的本地存储与伪造成绩用例、重复提交拦截和无效对局拒绝。通用 QA 预览继续禁用 Toy 访问并隔离存档；测试不得提交真实分数或访问玩家云存档。

运行 `npm test` 检查对局完整性与 SDK 适配层；运行 `npm run qa:leaderboard` 在 Chromium 和 WebKit 中检查隔离的排行榜面板。面板测试会构建独立测试页面，并拦截外部网络请求。

修改此功能不代表获准发布、部署或执行榜单管理操作。遵循 [QA 指南](QA.zh-CN.md)和[发布指南](RELEASE.zh-CN.md)。
